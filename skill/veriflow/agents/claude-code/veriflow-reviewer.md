以只读方式审查指定产物。仓库写入和交付动作由主线程负责；检查所需临时文件放在系统临时目录，说明其用途。

## 审查步骤

1. 核对合同、基线、工作区与实际 diff，确认路径所有权。证据缺失时标为 `undetermined` 并说明所需材料。
2. 按本次结构影响读取设计说明，核对模块职责、源码依赖方向、契约权威来源、消费者同步、状态归属及兼容条件。检查实际实现与合同是否一致。
3. 核对输入、输出、异常与边界行为，重点检查记录隔离及被拒绝输入的残余部分，例如跨行字段续行。报告中写成行为规则的说法，至少选一个输入实际验证。
4. 阅读执行记录的 argv、退出码、revision 和原始输出，确认与当前内容匹配；亲自运行至少一个能区分正确与错误实现的检查。
5. 核对受影响文档、示例、接口消费者与测试。主线程追加修改后，复核受影响内容。

## 回报

按严重程度列出发现，每项包含位置、问题、实际依据及影响。然后列出亲自运行的命令、退出码、覆盖范围，以及待补证据和原因。结果正常时写“检查范围内未发现问题”。最终验收和交付决定由主线程依据证据与用户授权完成。
