# 按文体组织写作

用于教程、README、设计/接口说明及工作报告。指导类内容写清动作、步骤、执行条件与完成标准，让读者沿实际路径完成并核验任务。

## 写作方法

依据文体、读者、用途和阅读方式选择结构。已有上下文足够时直接判断；各段围绕读者当前要理解或完成的事情展开。

| 类型 | 读者目的 | 组织重点 |
| --- | --- | --- |
| 教程 | 学习与跟做 | 承接前置知识，从场景或实验引出概念、机制与实践 |
| 操作指南 | 完成具体操作 | 前提、步骤、参数、预期输出与故障处理 |
| 技术参考 | 查询契约 | 对象、参数、结果、错误、版本与示例 |
| 设计说明 | 理解方案与取舍 | 问题约束、职责与依赖、契约、选择依据及影响 |
| 进度或交付报告 | 判断结果与下一步 | 结果、影响、证据、剩余工作与待决事项 |

README 按入口、快速上手或概览的实际定位组织；混合文档可按段落角色选择结构。

写清新增或改变的具体行为、原因与结果。必要时用前后对照、输入输出或最小示例连接原因与做法。用对象、条件、版本及输入范围表达精度。

沿读者操作路径核对命令、文件、接口和输出：创建与读取路径一致，参数与预期结果对应。样本用于参考表达方式，当前技术结论由当前实现与证据支持。

工作底稿区分亲自观察、他人报告与代理推断，保存来源及时间。正文在影响判断的位置说明来源与不确定性；失败、未运行检查、必要条件和待决事项紧邻相关结论。每项事实集中表达。

交付前核对事实、行为、因果、引用与实现状态，保留帮助读者判断的内容。计划、实现和验证分别表达，篇幅与术语按阅读目的选择。

代码行为或文档约定变化时，同一子任务内同步受影响文档与示例。共享文档由对应所有者更新；后续实现变化时，重新核验相关内容并标记失效证据。

## 选择报告载体

- 简单任务在最终回复中报告。
- 已有任务更新 `task-summary.md` 的当前状态，历史追加到 `work-log.md`，原始输出放在 `evidence/`。
- 复杂任务提供简明摘要及详细记录链接，需要下一执行者接手时创建交接包。

内部编号、权限字段和完整日志保留在记录中，正文解释影响读者判断的部分。

## 教程的附加要求

教程承接前置知识，从场景或小实验进入，由观察引出概念，再落到文件与命令。以内容准确、独立可跟做及实际学习结果验收，语言随上下文自然组织。

交付前从最终 Markdown 提取关键命令，按正文顺序与初始状态执行，核对参数、文件、输出和练习；用 `scripts/record_execution.py` 保存证据。源码、正文与封存可分阶段完成，相关内容同步后完成整体交付。

## 阅读负担

把正文、链接说明及必读记录一并计入阅读负担。信息保留一个权威位置，其余位置用有明确用途的引用连接。
