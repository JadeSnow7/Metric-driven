# 正式首轮独立评审合同（首组启动前冻结）

两名评审者分别在新上下文审查三个匿名标签产物，彼此不可读对方结论。主线程持有组名映射、裁决分歧；不称双盲。产品审查输入去掉运行组名及EDD专用过程记录；源代码与正文保持产物字节，若内嵌来源泄露不可在未记录下改代码，单列盲法限制。

每名评审者对三个产物分别执行相同冻结 evaluator（SHA256 6ed1a9d09fd40871b8e4e0bfed7cb2d2f64a4a3eb9f5ff762bb0566cda6fe86b），并保存自己的实际命令、原始结果、源文件hash。自动检查是外部协议校准，不证明四算法或真实进程。缺代码/入口无法运行即保留失败；不要替作者修复首轮。

## 必须独立核验

1. 首轮交付完整性：完整中文08正文、单Rust权威实现、真实Node域文件宿主、独立README/数据/例子入口、根verify收录、导航目录状态、8锚点和3独立练习。
2. 行为：默认精确16组合；同数据/任务/预算下实际四策略；动态事实变更、零预算零读取/调用、重复metadata、缺文件、非法path。读取与sources/claims/quality/实际输入一致，不准预置taskId/整题→答案，不把服务token或回放耗时混淆。
3. 源码与真实运行：按需在读取前按index选；window保留最近完整段落suffix；summary从实际资料摘事实而非预置摘要；retrieval基于实际正文评分。Rust掌握预算和结果采纳；StdioExecutor确实启动Node，callRecords来自实际执行。检查新增故障测试真正触发目标故障并断言系统反应；已退出/字段passed不能代替这一点。
4. 回归：TS typecheck/全部test，Rust fmt --check、check --locked、test --locked，05/06/07比较，真实hybrid正常/取消/崩溃，新增ch08异常，独立例子。构建环境故障与产品缺陷分列。
5. 按最终Markdown跟做：实际提取关键bash块（保留heredoc/参数），从读者起点执行根入口与三项独立练习，核对创建文件、参数、输出、解释；运行例子README自己的入口。代码文字不一致单列。不能因根test未收录而漏跑。构建文档、核对内部链接及受影响导航到08与09仍待实现；浏览器能力不可用应明确哪些仅静态核验。
6. 逐项比对作者声称通过与实际结果；指出错误检查名、未触发的fault、无实际断言、陈旧版本证据。实际对照原始命令与当前代码，不以记录格式为产品扣分依据。

报告以每产物的完整性/功能及回归/架构/正文复现分别列pass、fail、unverified及具体证据；不合成虚假精确总分。过程遵循与证据质量单独由原始运行审计补充。未知token/耗时字段留null；缓存input包含在input，reasoning包含在output，last包含在total，不相加。实现+写作+自验的总run与各测试命令时间不可当互斥成本相加。

三组全部首轮封存后才开始评分；评分与裁决封存后才创建C生产副本。生产修复的反馈、执行者、时间和成本另记，不回填首轮结果。仅三个单次运行，结论限定为共同详细产品方案之上额外加载skill的探索观察。
