# 08 上下文管理方法：同一份资料的四种取法

第07章解决了“历史太长怎么办”，本章把问题落到同一份六文档资料和四个任务上，观察哪些消息真正进入回答器，以及证据缺失时系统如何停在可解释的结果上。

<a id="methods-entry"></a>

## 从运行实验开始

```bash
npm run --silent ch08:compare
```

输出固定为四任务乘四方法的16行。每行包含 messages、读取操作、估算单位、来源、离线回答、质量和 StdioExecutor 的真实进程记录。估算是 UTF-8 消息单位，不是服务 token；本章不调用真实模型服务。

<a id="fixed-dataset"></a>

## 固定资料与回答边界

索引只保存标题、关键词、顺序和相对路径，事实只在 Markdown 正文。每条规则是独立 system message，问题是 user message，读取结果带 `[来源:docId]`。回答器只看 messages，不能读取 expectedFacts，也不能由 taskId 选择答案。

<a id="four-methods"></a>

## 四种方法

`on-demand` 先用标题和关键词筛选再读取；`window` 按 order 读取并从最早完整片段开始丢弃，调用与结果成对处理；`summary` 真实读取后只保留“字段：值”事实行，这是规则式离线摘要；`retrieval` 对问题词和索引关键词评分，稳定排序并记录 score。四者共用 Rust `context_methods`，通过既有 StdioExecutor 启动真实 Node 文件宿主。

<a id="compare-results"></a>

## 比较结果

任务一验证传输方式与协议版本，任务二验证发布检查命令，任务三跨批准与失败文档，任务四询问资料没有给出的生产吞吐量。`quality` 是有来源的必需事实比例；未知题 claims 为空且 `insufficientEvidence` 为 true。budget 为0在文档 I/O 前返回 `context_budget_exhausted`，modelCalls 和 operations 都是0。

<a id="method-failure"></a>

## 故障是可观察终态

缺失文件、越界路径、协议响应异常和 Node 宿主异常返回 `error`、answer 为 null，并保留真实 callRecords。记录中的派发、回收、pid、exit code 和终态来自进程生命周期，不能用 passed 字段替代行为。

## 独立练习

三项练习复制资料到绝对临时目录，不修改冻结 fixture。

<a id="practice-08-1"></a>

### 练习一：修改事实

复制 `fixtures/ch08-context` 到 `/tmp/rein-ch08-practice-1`，将 `docs/early-runtime.md` 的 `传输方式：JSON Lines` 改为 `传输方式：HTTP`，保留旧 oracle，然后运行：

```bash
npm run --silent ch08:compare -- --data-root /tmp/rein-ch08-practice-1 --strategy on-demand
```

核对 task-01 的 messages 与 `answer.rawAnswer` 使用 HTTP、来源仍为 doc-01，quality 按实际证据计算。

<a id="practice-08-2"></a>

### 练习二：零预算

```bash
npm run --silent ch08:compare -- --data-root /绝对路径/rein-ch08-practice-1 --budget 0
```

预期每行 `context_budget_exhausted`，messages、operations、callRecords 为空，modelCalls 为0。

<a id="practice-08-3"></a>

### 练习三：检索遗漏

```bash
npm run --silent ch08:compare -- --data-root /绝对路径/rein-ch08-practice-1 --strategy retrieval
```

修改 task-03 的 query 词后比较 selectedSources 与 score；缺少来源时 quality 下降，claims 不凭空补齐。本地回放不证明生产 token、延迟或容量。下一章第09章仍未实现。
