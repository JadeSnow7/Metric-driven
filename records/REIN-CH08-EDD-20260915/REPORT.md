## 评审与主线程负担

两名独立评审读取去除组名的副本，分别运行关键行为并跟做正文；主线程知道匿名映射，所以不称双盲。产品评分不要求 EDD 专用记录格式；流程与证据质量单列。

冻结评估器遗漏了工具消息字段的估算和 tool 来源适配，产生误判。保留原结果后，主线程要求对窄范围补充检查校准，再统一应用三组，纠正估算判断；没有更换成对 C 有利的独立标准。评审还出现公共 Cargo target、错误输出目录、外层 PWD 展开、ENOSPC 与 loopback 权限问题，全部保留为方法/环境偏离。

生产阶段主线程的定向指导仍不可缺少：修复错误评分、预算越界、段落身份、英文碎片检索；要求工具记录对应真实输入；纠正未触发故障的测试、空集合断言、工具消息角色假设、超大预算只测 JS 包装等方法问题；推动正文、独立示例和导航同步。由于重复失败，核心、合同测试、正文和归档分开，旧测试 owner 被停止后换用全新 coder。次数、执行者与失败输出见 [production](production/) 及 [反馈记录](production/feedback.md)。

## 成本与结论边界

- 原始 token 字段保留在 [costs](costs/)。缓存输入包含在 input 中，reasoning 不再与 output 重复相加。阶段不能可靠拆分时保持 null，不估算费用或节省比例。23条归档usage按会话、turn和精确记录时间与源数据逐项匹配，见 [原始usage核对](costs/primary-exact-usage-audit.json)；主线程as-of快照仍不包含最后回复的完整成本。重试、评审和生产返工不混入正式首次运行。
- 三组各一次，顺序 A→B→C，使用共同详细方案、模型路由与停止规则。存在共享系统、下载缓存和 /tmp 访问，不能证明严格 OS 隔离。
- 本轮评估的是共同详细方案之上额外加载 skill 的效果，不代表整个 EDD 工作流的因果收益，也不能推广到其他章节或真实模型服务。
- 摘要与回答器都是规则式离线实现；上下文估算单位不是服务 token，本地回放耗时不是真实模型延迟、吞吐量或质量指标。独立 Node 进程不是安全沙箱。
- 评审中未能完成的网络回归与 GUI 检查仍按当时版本保留未判定/未运行；后续生产验证只能证明生产版本，不能回填首轮。
