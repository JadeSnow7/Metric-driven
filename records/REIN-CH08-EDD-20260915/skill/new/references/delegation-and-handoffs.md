# 委派与交接

## 什么时候委派

仅在子任务边界明确、文件所有权可隔离、并行能带来实际收益且环境允许时委派。源码实现优先给自定义 coder 子代理；需求澄清、架构取舍、共享协议、最终 diff 审查、整体门槛和用户沟通留在主线程。

没有子代理时直接完成并记录“由主线程实现；未进行独立代理审查”。不要把同一代理的第二遍阅读写成独立审查。

## 写入所有权

- 一个文件同一时间只有一个写入所有者；共享状态文件由主线程维护。
- 子代理修改前获得明确的文件范围与基线；源码、正文、验证和封存可以由不同 owner 分阶段完成，交接列出尚未同步的依赖。整体交付在正文或验证未同步时仍未完成，不要求每个源码 coder 同时承担全部教材和归档工作。
- 需要改共享接口时先向主线程提交建议，主线程更新约定后再分派。
- 代理完成后，主线程检查实际 diff、证据和接口影响；代理自报状态只作为线索。

## 子任务完成回报

每个已划分子任务一完成就回报：结果、实际产物路径、验证状态与证据、受影响文档是否已同步、下一依赖或阻塞。主线程先核查回报，再在当次进度更新告知用户并更新摘要；未核查的结果标为完成待审查。回报不等于提交或新建会话，也不改变授权。

## 最小充分交接包

只有确实需要另一位执行者继续时才创建交接包。每次实现、跨 Agent、暂停或换会话交接至少包含：

1. 编号（`MT-*` / `IT-*`）与目标；
2. 来源；
3. 基线提交、worktree 和改动所有权；
4. 范围、文件范围、接口约束与依赖；
5. 指标、验收方法和证据路径；
6. 已采纳决策与未决问题；
7. 只保留会影响下一步的失败经验；
8. 下一步、停止条件和相关路径。

使用 `assets/templates/handoff.md`。交接包是上下文边界，不是完整历史转储；已在当前摘要或证据中的内容直接引用路径，不要复制。

交接必须写明来源 revision、目标 base、可写路径和逐文件出口。整合前使用 `scripts/integrate_boundary.py` 校验并逐文件复制；路径越界、版本漂移、来源缺失和冲突应失败且不覆盖目标。工具强制的是这些可计算条件，评审结论和交接纪律仍由代理负责。

最小调用示例：`python3 scripts/integrate_boundary.py --source-root /tmp/source --target-root /tmp/target --manifest manifest.json --source-revision REV --target-base BASE --allowed-path src`。manifest 必须包含 `source_root`、`target_root` 和 `files`；每个文件项必须包含 `source`、`source_sha256`、`target_sha256`。

## 写作文档的附加信息

跨 Agent 写作另加：大纲、术语表、事实来源、章节归属、引用格式和整合负责人。只有需要交接写作工作时使用 `assets/templates/writing-handoff.md`；其中没有内容的字段可以省略。

写作者只维护自己章节与证据；整合负责人处理交叉引用、术语一致性、事实冲突和最终结构。不得让多个代理同时改主稿。行为、接口、命令、配置、路径、章节约定或实现状态变化时，写作者在同一子任务内同步其负责文档与示例；共享文档由整合负责人串行更新。未同步的相关文档记录为未完成项。

## 独立行为评估

复杂或高风险 skill/流程可安排独立前向评估：给评估者真实请求、skill 路径和最少原始材料，在隔离临时目录生成结果。不要透露预期答案或已知缺陷。主线程审查实际产物，只根据观察到的问题修订。

评估不应触发生产写入、外部发布或昂贵调用；若需要新增权限，先停下询问。
