# REIN ch05–16 公共产品规格

本规格只描述交付物和可观察行为，适用于 TypeScript 与 Rust 实现。已有手工正文作为现有材料保留，新增内容不得覆盖它。

交付包括 ch05–ch16 各一篇 TypeScript 正文和一篇 Rust 正文（共 24 篇），每篇都能从对应仓库状态开始执行。正文必须说明承接问题、运行命令、输入与预期输出、关键实现、失败处理和练习；两种语言使用相同章节编号、锚点、练习编号及行为验收。章节需要的独立示例在 ch08、09、11、12、14 各提供 TypeScript 与 Rust 版本，共 10 个；阶段汇总 1–3 和附录 A.1–A.5 与章节链接同步。

章节能力按验收清单中的可观察行为交付：ch05 工具循环与事件；ch06 预算、重复、取消、超时；ch07 规则／目标／历史／结果的上下文管理；ch08 按需读取、窗口、摘要、检索四法及统一比较入口；ch09 结构化验收与多种验证器；ch10 分类反馈、有限修复、重规划和人工接管；ch11 参数、路径、信任边界、凭据和幂等防护；ch12 权限、差异、基线绑定和批准后应用；ch13 依赖、审查节点、持久化恢复和副作用未知处理；ch14 有界委派、预算、取消、证据汇总和冲突检测；ch15 本地 stdio MCP 文档检索、权限、超时和清理；ch16 发现文档差异、检索依据、提出补丁、批准应用和验证。

所有功能验收必须有可运行的离线输入和结果证据。退出码为零只能证明进程结束；必须同时满足清单要求的产物、输出、测试数量和行为断言。缺失命令、未运行、缺失或哈希过期的产物、零测试均不得计为通过。真实模型／外部服务调用单独记录，缺失用量写 `null`，不得推算 token 或延迟。

测试 runner 名称和输出中的测试数量只是可观察 provenance 检查，不是抵抗恶意命令伪装的独立证明；调用方必须在执行前冻结 argv、工作目录和 source 指纹。

文稿是否完整、可跟做、解释是否充分由人工审查；机器评估将文稿质量保持为 `unreviewed`，不会因为文件存在、关键词或字数自动宣布通过。等价地满足语义验收的实现允许不同源码和补丁字节表示。
