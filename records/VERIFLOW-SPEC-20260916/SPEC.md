## 不变量与取舍

1. 不删除失败或历史证据消除错误；记录完整性不等于语义验收。
2. 采用 schema 1.3（1.1/1.2 兼容路径保留且显式提示没有新绑定）；新验收不得把旧记录升级成已绑定。
3. 小模型：产品指纹 + Spec 内容指纹（含完整声明规范、引用契约文件字节、指标的验收定义）+ 显式运行回执路径。状态/结果/证据引用等回执字段不进入 Spec 规范投影。Spec 规范内容引用一个权威位置；产品交付物可覆盖元数据排除，不忽略整个 records 或 Markdown。声明/分类变化本身进入绑定。默认全产品/全 Spec 保守失效，不建细粒度依赖图。
4. 外部输入采用 task-state 中明确列出的精确文件身份与复现说明，规范化路径与哈希一致检查；仓库内路径保持可移动性。历史旧格式外部记录仅审计保存，不自动变成可用新证据。
5. 执行时授权快照在动作执行前捕获用户来源内容、来源标识、授权/范围、目标/revision、时间及内容摘要。当前来源 adoption 改变不追溯改变快照；快照不是密码学用户签名，主线程核实来源真伪。旧记录没有快照保持未知。
6. 主线程维护本 Spec、本轮记录、审查与裁决。coder 独占代码/测试/配套文档，在隔离副本工作，不直接回写原目录；不擅自降低成功条件。
