# ch06 循环控制实施交接

只有主线程明确宣布 ch05 生产代码、正文、快照通过后才可执行。本文件是行为与验收方案，不授权提前修改未冻结的前置。实现和两篇正文均由 coder 完成；主线程审查实际 diff 和证据。

在 ch05 的同一个运行循环上引入控制，不另写只会打印停止原因的模拟循环。保留已有公共调用的兼容默认值。模型步数表示真正派发的模型请求数，工具预算表示真正派发的工具调用数，计数单位在正文写清楚；达到预算后不派发下一项。同轮请求多个工具时，执行顺序和数量可检查，未执行项应在事件中明确标记，不能伪装成实际工具输出或在后续请求里形成悬空配对。

重复行动以工具名与规范化参数为身份，不能仅比较调用 ID；同义 JSON 键顺序不应绕过检测。阈值可配置，阈值定义为容许派发次数或触发次数必须明确且两语言一致。正常任务不会被默认设置误停。

至少支持一次运行的外部取消信号和整体截止时间；可另有单次请求超时，但必须区分定义。取消前、模型等待中、同轮工具之间和超时之后都不再派发新动作。对可取消传输向下传递取消；不支持取消的适配器的迟到响应隔离丢弃，不能变成成功结果。测试不要仅检查布尔标记：记录实际请求/工具开始次数，在取消或截止后再等待一个可观察间隔确认数量没有增长。

测试包含正常三轮搜索读取、多调用预算截断、重复参数而不同 ID、外部取消发生在模型等待中、迟到响应、整体超时、零预算以及既有 ch05 行为回归。两语言使用同一控制场景规范化输出比较停止原因、计数和派发顺序。时间测试使用短但合理的余量或可控时钟/同步屏障，避免只依赖脆弱的1ms调度竞赛。

给出从仓库根运行的双语言示例命令，通过参数选择上述可观察场景。正文 `06.md`、`06-rust.md` 从 ch05 的基本32轮保护不足说起：先复现浪费，再逐步引入预算、重复身份、取消和截止时间；用实际关键源码解释控制检查应放在哪里。语言解释围绕实际实现的信号/异步和资源生命周期。共享锚点与练习 06-1、06-2、06-3 对齐，包含改变阈值、取消时机、同轮多调用预算的可执行验收。
