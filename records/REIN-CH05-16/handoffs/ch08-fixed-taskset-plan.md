# ch08 固定任务集的准备要求

此项是实验开始前的共同输入准备，单列成本，不计任一组实现成绩。只在 ch07 前置验收后物化并封存；不得让两组自行选择不同材料或预算。评估不是比较真实模型性能。

准备六份普通 Markdown 文档，保留稳定文档 ID、标题、顺序和来源路径：运行配置、缓存配置、批准规则、文档索引、失败处理、发布操作。每份有可辨认的事实与不含答案的背景段落。全文总量应大于各策略共用的上下文预算，单份关键事实及必要规则/目标能够放入预算。固定材料字节、文档顺序、索引、任务顺序和预算，生成 hash 清单。事实可以采用明确的 `字段：值` 形式，离线适配器能力必须公开说明。

至少四项固定问题：

- 单来源问题：从较早的运行配置中找出传输方式和协议版本。
- 较新来源问题：找出发布操作中的检查命令。
- 跨来源问题：结合批准规则与失败处理，说明文件基线变化后的批准状态和处理动作。
- 缺少依据问题：询问材料没有给出的生产吞吐量，正确结果是证据不足，不能编造数值。

每项给共同问题、必要规则、预期事实或无法判定条件、相关来源；不按策略预置分数。每次四种策略使用完全相同的原始材料和该任务预算。可以选择一个预算，但必须在两组执行前固定。估算器要记录单位/算法，服务报告 token 字段为 null。

按需读取必须从索引选择后读取实际文件；窗口按固定顺序保留最近完整片段；摘要必须从实际材料产生更短内容，并能追溯压缩来源；检索根据问题选择相关片段。构造的上下文实际送入统一回答器，回答器不得按策略名称分支或读取评估答案。评审会将临时副本中的一个关键事实改成新值，确认输出来源于新上下文，防止预填答案掩盖机制。

结果保留问题、策略、选中来源、实际上下文、估算用量、原始回答、逐事实判定与本地墙钟耗时。信息丢失或检索遗漏的反例可用额外的公开扰动输入，不覆盖固定任务集。不同策略可能同分，不为展示差异而篡改材料或评分。

物化作者把完整准备包交主线程复核后，两个 ch08 正式 coder 接收完全相同的包。最终记录精确 hash 与准备成本。
