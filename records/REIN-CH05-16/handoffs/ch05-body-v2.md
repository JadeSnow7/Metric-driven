# ch05 两篇中文教程的生产修复

执行者只能写 `docs/chapters/05.md` 与 `05-rust.md`，以及自己独立的跟做证据。代码与合同由 ch05_code_repair_v2 独占。先取得其冻结的公共 CLI/API，再写与真实实现相符的内容。不是首轮对照，不修改首轮评分。读取冻结 skill 及其 writing 引用，参考现有 01 的教学推进方式，但不复制其中未成立的历史标签或手工稿错误。

读者产出应是理解并能改写的完整循环，正文不能只列入口和概念。两篇共享知识点锚点、练习 ID 和验收事实，语言解释根据实际代码各自展开。不要用固定字数代替质量，也不要用一页概要声称完整。

建议的具体教学路线：

1. 从一次模型请求无法自行取得仓库事实切入：明确这一章补充了最小接入工程，00–04 不因此成为已完整交付。列出实际模块和安装前提，从仓库根开始写命令，所有后续命令标明当前位置或统一根目录。
2. 建立一份可复制的新实验目录，包含两份不同主题、都带搜索标记的文件。先运行 single，展示实际输出。再运行 multi，展示搜索结果、两个读取结果、最终答案；修改文件事实重跑，让读者亲见答案来自当前输入。不要让新增文件被默认前两条命中规则悄悄忽略。
3. 用真实源码中一段一段的关键代码构造机制：定义 Message/ToolCall/ModelTurn；注入一次模型调用接口；首轮消息；循环迭代；追加 assistant；按顺序分派工具；按 id 追加 tool；下一次模型请求；最终回答与停止。每段都解释为什么需要、输入输出是什么、在完整源码哪里，片段不能引用不存在 API。辅助协议 JSON 展示第三次请求中两条 read 的对应关系。
4. 在上述代码旁解释语言知识：TS async/Promise、接口及判别联合如何让不同角色消息被检查；Rust trait/Result/enum/借用和拥有的数据、serde 映射如何服务该循环。只解释本章真正使用的技术，不加入泛泛语法百科。
5. 从真实事件展示状态变化和检查方式，说明事件足以检查当前请求，不把它表述为持久恢复系统。明确正常终止、空回答、模型错误和基本32轮保护；更细预算/取消/超时留给06。
6. 给出完整可复制的失败实验，使用当前交付 CLI 模式/测试入口和精确参数：missing 后反馈并恢复、模型/回放耗尽错误、空回答或上限。提供实际输出摘录与原因，不能让读者猜改哪个不存在的响应队列。
7. 显式 live 命令复用 REIN_*，说明最多4轮、无自动重试；离线主体不需要密钥。不要写主机绝对路径，不在正文引用基准评分/代理流程。
8. 至少三项共享练习：05-1 使用自建两文件目录并验证第三次模型输入中的 read 结果；05-2 缺失文件后正确反馈/重读且 id 配对；05-3 对照 empty_final 与 max_turns 的精确终止结果。每项给输入起点、修改位置或完整命令、可观察验收，避免只写“自行实现”。

完成后自己严格按两篇正文从根目录执行每个有副作用的离线实验，保存 argv/cwd/exit/stdout/stderr。安装命令可复用已安装锁定依赖并明确记录，真实服务本轮不运行。给主线程全文及跟做证据；正文不过关则不能进入 ch06。
