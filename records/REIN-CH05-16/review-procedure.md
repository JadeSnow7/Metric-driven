# 章节首轮评审与生产验收

两组首次结束后，各自封存完整源码/正文载体、内容清单、相对共同起点的补丁、共同输入哈希、原始事件和最终回复。任何评审或修复发生在封存之后；修复前复制为生产候选，首轮文件不覆盖。

评审包用无组名的代号。两名评审各自获得两个包的源码、正文、共同规格和必要的复跑环境，不获得受测 skill、作者终结报告、实验组映射或 EDD 记录。作者终结报告与日志由主线程另外核对声明真实性。代号遮盖不能消除文风等间接线索，所以这是去标签评审，不是双盲。

每名评审逐包交付以下结果，并为每个问题写明文件位置、具体触发输入或可复跑命令、观察到的结果和影响：

- 功能：公共验收的每项正常/失败行为，在两种语言中分别为 passed、failed、undetermined 或 not_run。检查真实工具/外部进程路径是否实际被调用，不能用自带测试数量代替行为验证。
- 一致性：共享输入的可见结果与错误分类，检查没有遗漏一种语言、独立示例或既有回归。
- 教程：逐篇按文中目录、命令和参数跟做，核对输出、源码说明、失败处理、练习及共同锚点。机器统计仅辅助定位；完整性和解释是否充分由实际阅读及跟做判断。
- 证据：列出亲自执行的检查和结果；无法运行说明原因。不对作者是否采用某种流程模板评分。

主线程逐条核对实际 diff、关键反例及两份评审。分歧保留两方依据，再给裁决；必要时在副本中复现。未完成正文或缺语言属于首轮交付不完整，正常终结不能改记为资源中断。没有运行的真实服务保持 not_run/undetermined，不影响已通过的独立离线检查，但不能写整体真实服务通过。

产品成绩保持逐项分类与缺陷清单，不事后发明总分权重。成本单独记录：准备、实现与写作、可观察验证命令耗时、评审、生产返工；无法可靠拆分的阶段标明合并值或 null。可取得的 token 来自原始运行 usage，不根据字数估计。事件接收时间只作为本地观测的时间信息，不能冒充模型计算时间。

最终生产候选经过修复及整合门槛后形成下一章快照；通过首轮与生产最终结果分别保留。共同起点来自此前已修复验收的 skill 组产物，这一依赖条件必须进入最终报告。每章各组一次，只给本项目的探索性观察，不推导统计显著性或固定节约比例。
