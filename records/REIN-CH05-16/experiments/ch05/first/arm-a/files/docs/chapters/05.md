# 05 核心 Agent Loop

一次模型请求只能得到一次决定；当模型要求搜索和读取时，程序必须执行真实工具，把结果按原调用 ID 放回消息历史，再发起下一轮。本章实现这个循环，预算、取消和超时留到第06章。

## 运行离线演示

在仓库根目录执行：

```bash
npm ci
npm run typecheck --workspace ts
npm run ch05:offline --workspace ts
```

演示临时写入 `guide.md`，确定性模型先请求 `search_files`，再请求 `read_file`，最后回答。输出应包含 `search-1`、`read-1`、真实文件内容和 `"reason": "completed"`。回放只决定下一步，工具输出来自当前工作区；修改文件内容后，读取事件也会变化。

## 循环如何工作

`ts/src/rein/loop.ts` 的 `runAgentLoop` 保留 `messages` 和 `events`。assistant 消息中的多个 `toolCalls` 按声明顺序执行，并追加：

```text
toolCallId="search-1" -> role="tool", content=真实搜索结果
toolCallId="read-1"   -> role="tool", content=真实文件内容
```

适配器下一次收到完整历史，因此不会把结果错配给别的调用。没有工具调用且文本非空才是 `completed`；空文本是 `empty_final`。未知工具、参数错误、越界或读取失败都会成为结构化失败，模型错误则成为 `model_error`。默认 32 轮后停止为 `max_rounds`。

事件同时记录轮次、调用 ID、工具结果和停止原因，可检查并重放运行过程；事件不是给模型的历史，真实工具消息仍必须送入下一轮。

```bash
npm test --workspace ts -- --run tests/loop.test.ts
```

测试覆盖最终回答、搜索→读取、同轮多调用 ID 顺序、失败反馈、模型失败、空回答和轮次保护。真实模型接入应复用已有 `createOpenAIAdapter`，显式提供 `REIN_*` 配置并把本章冒烟限制在 4 次以内；离线流程不读取密钥。
