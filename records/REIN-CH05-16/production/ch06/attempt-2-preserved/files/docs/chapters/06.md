# 06 循环控制

上一章的循环有一个保护：最多请求 32 次模型。这个上限只能阻止无限增长，不能说明为什么停止，也不能阻止同一个读取动作被不同的调用 ID 重复派发。本章把控制条件放进真实的 `runAgentLoop`，让模型请求数、工具启动数、重复身份和取消都能从事件中复核。

<a id="loop-entry"></a>
## loop-entry：先观察没有控制的浪费

在仓库根目录执行下面的命令。示例会创建临时目录和真实 `README.md`，运行结束后清理目录；它不调用模型服务。

```bash
npm run ch06:offline --workspace ts -- duplicate
```

输出 JSON 中可以看到第一次 `read_file` 的 `tool_result`，第二轮虽然调用 ID 已变为 `duplicate-2`，参数仍是 `{"path":"README.md"}`，因此出现 `action_skipped` 和 `duplicate_action`。`requests` 为 2；第二次模型确实被请求，第二次工具没有启动。

<a id="budget-and-stop"></a>
## budget-and-stop：把预算变成派发边界

`maxTurns` 是实际开始的模型请求数，`maxToolCalls` 是实际进入工具分派的调用数。模型一次返回多个调用时，循环逐个检查预算；超出部分只记录 `action_skipped`，不会伪造工具结果，也不会把未执行调用放进下一轮消息。

```bash
npm run ch06:offline --workspace ts -- budget
npm run ch06:offline --workspace ts -- zero
```

`budget` 的结果是 `tool_budget_exhausted`，只有一个 `tool_result`；`zero` 在加入第一条用户消息后直接以 `max_turns` 停止，模型请求数为 0。

<a id="search-read"></a>
### search-read：正常任务仍然按工具结果前进

```bash
npm run ch06:offline --workspace ts -- normal
npm run ch05:offline --workspace ts -- workspace ./fixtures/workspaces/prerequisites multi
```

模型先读取真实临时文件，下一轮才生成 `完成：marker: ch06`，所以控制条件没有误停正常任务。

<a id="cancellation"></a>
## cancellation：取消和截止时间

`AbortController` 是一次运行的外部取消信号。控制器在发模型请求前、模型返回后和同轮每一个工具前检查它。等待中的模型请求通过 `Promise.race` 隔离迟到结果；适配器若支持 `AbortSignal`，也会收到同一个信号。

```bash
npm run ch06:offline --workspace ts -- cancel
npm run ch06:offline --workspace ts -- timeout
```

这两个场景分别返回 `cancelled` 和 `timeout`。整体 `timeoutMs` 覆盖模型等待和工具之间的间隔；它与单次 HTTP 适配器自己的超时是不同层次的限制。

## 机制走读

`ts/src/rein/loop.ts` 的 `controlReason` 将信号和截止时间转换为结构化停止原因；`raceControl` 负责在模型迟到时让当前循环先返回。每次工具派发前以 `name + canonicalJson(arguments)` 生成身份，`canonicalJson` 对对象键排序，所以不同 ID 或键顺序不能绕过重复检测。工具结果仍由上一章的只读分派器产生。

TypeScript 的 `AbortSignal` 是可观察状态，不会自动杀掉任意 Promise。循环通过竞争控制 Promise 隔离迟到值，`finally` 清理定时器和监听器。`additionalProperties: false` 是发送给模型的 schema 声明；真正的路径和参数边界仍由 `dispatchReadonly` 检查。

## 练习

<a id="practice-06-1"></a>
### 练习 06-1：改变重复阈值

把 `duplicateLimit: 1` 改成 `duplicateLimit: 2`，运行 `duplicate`。应先得到两次真实 `tool_result`，第三次才 `action_skipped`；恢复为 1 后只应启动一次工具。

<a id="practice-06-2"></a>
### 练习 06-2：改变取消时机

在 `ts/examples/ch06-loop.ts` 中把取消定时器从 5 改为 0，再改为 50。观察 JSON 的 `model_requested` 与 `tool_result` 数量，不要只看退出码。

<a id="practice-06-3"></a>
### 练习 06-3：同轮多调用的预算

把 `budget` 的 `maxToolCalls` 改为 2。两个调用都应有真实结果；改回 1 时第二个调用只有 `action_skipped`，消息历史不应出现它的 `toolCallId`。
