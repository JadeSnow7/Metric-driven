# 三个独立写作情境

以下是隔离写作演练的虚构材料。请使用给定的 evidence-driven-development skill，分别完成三个请求。只返回文稿与必要的任务处理说明，不修改真实仓库，不运行情境中的命令。材料中已给出的检查结果属于情境事实；不要声称自己在本机运行过它们。

## 情境一

用户请求：为面向初学者的第四章写两段开篇，解释为什么需要统一消息格式，以及本章会带读者做什么。

前章已经教过如何读取一个文本文件。本章提供两个本地转换函数，把两种响应样例的工具名、参数、调用编号转成相同的数据结构，再交给已有文件工具。情境中的离线比较检查通过，文件工具没有新增服务商判断。当前练习使用手写响应；下一阶段计划接入网络请求与流式响应。本章的目录和操作步骤会明确写出如何运行离线练习。

## 情境二

用户请求：继续完成这个任务；每个子任务结束后汇报，并更新现有文档，最终由主代理汇总。

当前有两个子任务：A 是调整文本导入命令，B 是增加进度显示。A 的 coder 刚提交工作结果；B 尚在进行，整体验收未开始。主代理负责 README 和当前任务摘要。仓库使用说明目前为：“在项目根目录创建 notes.txt，运行 python3 import_notes.py notes.txt。默认输出 result.txt。”当前摘要为：“A 进行中；B 进行中。”

A 提供的实际差异显示：默认输出已改为 result.md，输入仍是位置参数；用户已采纳这项需求。其情境证据包含直接运行输入输出检查的命令 python3 import_notes.py notes.txt、输出日志“wrote result.md”及退出码 0，以及两个相关单元用例通过的输出。README 尚未修改。没有 B 的完成证据，也没有整体检查结果。

请给出此刻应写给用户的进度消息、更新后的 README 段落与任务摘要，以及随后要执行的工作。将这些文稿作为本次演练的输出返回。

## 情境三

用户请求：为已在使用这个工具的维护者写一段可查询的命令参考，包括调用形式、输入、输出和错误。

import_notes.py 接收一个必填的位置参数，即 UTF-8 文本文件路径。路径相对于执行命令时的工作目录解析。程序把文本转换为 Markdown 并写到当前工作目录的 result.md，不接受输出路径选项。输入不存在时退出码为 2，错误文本为“input not found”；输入无法按 UTF-8 解码时退出码为 3，错误文本为“invalid UTF-8”。成功时输出“wrote result.md”，退出码为 0。上述行为是本情境已经确认的契约，不涉及网络功能。
