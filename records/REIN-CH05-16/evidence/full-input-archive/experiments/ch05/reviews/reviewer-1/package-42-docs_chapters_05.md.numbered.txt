   1 # 05 核心 Agent Loop
   2 
   3 前面已经有消息、工具和模型适配器，但各调用一次还不是 Agent：模型必须看到工具结果，再决定下一步。本章让模型先搜索、再读取，最后根据真实文件内容回答。离线回放只替代模型请求，搜索和读取仍访问工作区。
   4 
   5 <span id="ch05-loop"></span>
   6 <span id="message-tool-pairing"></span>
   7 
   8 ## 1、运行 TypeScript 示例
   9 
  10 在仓库根目录执行：
  11 
  12 ```bash
  13 npm ci
  14 npm run typecheck --workspace ts
  15 npm run ch05:offline --workspace ts
  16 npm run ch05:offline --workspace ts -- single
  17 ```
  18 
  19 示例使用 `fixtures/workspaces/prerequisites/`。不带参数是多文件搜索后读取；加 `single` 是单文件读取。两种模式都真实执行工具，输出应包含 `"state": "completed"` 和 `"reason": "final_answer"`，事件中能看到真实命中的 `README.md` 和读取文本。
  20 
  21 <span id="tool-loop-mechanism"></span>
  22 
  23 ## 2、循环、配对与状态
  24 
  25 一次模型调用只知道对话和工具声明；模型返回工具调用时还没有读到文件。每轮流程是：
  26 
  27 ```text
  28 用户 → 模型 → assistant(tool_calls) → 按声明顺序执行
  29      → tool(toolCallId, content) → 下一轮模型 → 最终文本
  30 ```
  31 
  32 `toolCallId` 是配对关键。assistant 保留完整调用数组，每个结果恰有对应 id；同轮两个调用不能丢掉一个或按完成快慢重排。`ts/src/rein/loop.ts` 的 `runAgentLoop` 维护 `messages` 和可序列化 `events`：`model_requested`、`model_received`、`tool_result`、`stopped`。停止原因是 `final_answer`、`empty_final`、`model_error` 或 `max_turns`。
  33 
  34 只有无工具调用且去空白后非空的文本才成功。默认最多 32 轮是本章的基本保护；预算、取消、超时和重复检测留到第 06 章。
  35 
  36 <span id="failure-paths"></span>
  37 
  38 ## 3、失败路径
  39 
  40 未知工具、参数错误、路径越界和文件不存在都会成为结构化失败 `ToolResult`，再作为 tool 消息交给模型；程序不会把失败伪装成文件内容。模型适配器抛错时保存已经产生的事件，以 `model_error` 结束且没有假答案；空回复以 `empty_final` 结束。
  41 
  42 运行完整测试：
  43 
  44 ```bash
  45 npm test --workspace ts
  46 ```
  47 
  48 `ts/tests/loop.test.ts` 覆盖真实临时文件、同轮多调用的 id 顺序、错误反馈、模型失败、空回复和轮次上限，并断言第二次模型输入实际包含工具结果。
  49 
  50 <span id="event-replay"></span>
  51 
  52 ## 4、事件重放与真实入口
  53 
  54 `LoopResult.events` 是运行轨迹；保存 `JSON.stringify(result.events)` 后可重建每轮请求、调用 id、工具结果和停止原因。它是本章的可观察重放证据，不是第 13 章的持久化恢复。
  55 
  56 真实程序可把已有 `createOpenAIAdapter` 传给 `runAgentLoop`，配置沿用 `REIN_BASE_URL`、`REIN_API_KEY`、`REIN_MODEL`。本章离线命令不读取 key、不访问外部服务；真实冒烟应限制调用次数且不自动重试。

  60 ## 5、练习
  61 
  62 ### 练习 05-1：改变输入
  63 
  64 复制 fixture 工作区、修改 README 并让示例使用新目录。验收：搜索 output 和第二轮 tool message 反映新文本。
  65 
  66 ### 练习 05-2：修正失败调用
  67 
  68 让第一轮读取不存在路径，第二轮读取正确路径。验收：先出现 `ok: false`、`path_invalid` 且 id 一致，最终仍由第二轮决定。
  69 
  70 ### 练习 05-3：检查停止
  71 
  72 分别回放空文本、抛适配器错误、连续工具调用。验收原因分别为 `empty_final`、`model_error`、`max_turns`，三者都没有 `answer`。
  73 
  74 本章完成了“思考—行动—观察—再思考”的最小骨架；下一章再增加控制策略。
