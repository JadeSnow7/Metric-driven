# 05 核心 Agent Loop

你已经可以发出一次模型请求，也有了只读的 `search_files` 和 `read_file`。但“模型说请先找文件，再打开文件”并不是一次请求能完成的：程序必须执行工具，把真实结果放回下一轮消息，再让模型决定下一步。本章把这个过程写成可重放的核心循环；预算、取消、超时和重复调用仍留到第06章。

<span id="知识点-循环与工具结果配对"></span>

## 先准备一个不需要密钥的实验

在仓库根目录安装依赖，然后进入 TypeScript 目录：

```bash
npm ci
cd ts
npm run typecheck
npm run ch05:offline
```

这个演示使用确定性模型回放，但文件不是回放里的答案。程序临时创建 `guide.md`，模型先请求搜索，再请求读取；两个工具都实际访问工作区。输出会包含 `search-1`、`read-1`、`"reason": "completed"`，并能看到“工具结果会进入下一轮”。

为了理解输入，演示等价于把用户问题放入：

```text
搜索并读取 guide.md
```

回放只决定模型下一步要什么，不能替代工具的输出。你把临时文件内容改成另一句话，再运行一次，最终事件中的读取内容也会改变。

## 模型消息为什么要继续带着历史

循环的每一轮都调用 `ChatAdapter.complete(messages, tools)`。模型返回的 assistant 消息可能没有文本，却有多个 `toolCalls`。程序按声明顺序执行它们，并分别追加一条 `role: "tool"` 消息：

```text
assistant: toolCalls=[{id: "search-1", ...}, {id: "read-1", ...}]
tool:    toolCallId="search-1", content=真实搜索结果
tool:    toolCallId="read-1",   content=真实文件内容
```

`toolCallId` 是关联键，不能只按“最近一次工具”猜测。OpenAI 适配器会把它序列化为 `tool_call_id`；因此下一次模型请求同时看到了原 assistant 调用和每个匹配结果。Anthropic 适配器则把同样的历史转换成 `tool_use` / `tool_result`，循环本身不依赖供应商。

## 运行单元测试，观察失败也属于状态

```bash
npm test --workspace ts -- --run tests/loop.test.ts
```

测试覆盖最终回答、搜索后读取、同轮多调用的顺序和 ID、未知工具反馈、模型错误、空回答及默认轮次保护。其中未知工具不会被包装成成功文本，而是进入结构化错误：`{"error":{"code":"unknown_tool",...}}`。模型随后可以解释失败或选择别的动作；若模型适配器本身失败，循环停止为 `model_error`，不会伪造回答。

## 对照关键实现

打开 `ts/src/rein/loop.ts`。`runAgentLoop` 保存 `messages` 和 `events` 两个序列。每次模型调用先记录 `model` 事件；每次工具调用记录包含名称、调用 ID 和完整 `ToolResult` 的 `tool` 事件。正常结束必须同时满足“没有工具调用”和“文本非空”，并记录 `completed`。达到默认 32 轮时记录 `max_rounds`，这只是基础保险；更精细的预算与取消在下一章实现。

事件序列是轻量的运行证据：它能重放“模型请求了什么、工具返回了什么、为何停止”，而不是只留下最终字符串。要注意事件本身不替代消息历史，下一轮仍必须发送实际工具内容。

<span id="failure-paths"></span>

## 失败路径怎么读

路径越界、文件不存在、参数类型错误和未知工具都会由只读路由返回 `ok: false` 及错误码，仍按原调用 ID 生成一条工具消息。这样模型能看到失败；循环也不会因为一次工具失败而误报“读取成功”。模型解析失败或网络错误属于适配器错误，结果为 `model_error`。模型返回空文本且没有工具调用则是 `empty_final`，不是成功。

本章离线演示没有读取 `REIN_API_KEY`，也不访问外部服务。后续真实冒烟可以复用已有 `createOpenAIAdapter` 和 `createFetchTransport`，但应由调用者显式提供 `REIN_*` 配置，并把 `maxRounds` 设为不超过 4；本章不替你读取密钥。

## 练习 05

任务：在 `ts/examples/ch05-loop.ts` 中再增加一次读取失败的模型回合，让模型先调用 `read_file` 读取不存在的路径，然后返回一句解释；同时把临时 `guide.md` 的内容替换为你自己的句子。

可观察验收：运行 `npm run ch05:offline` 时，事件中出现对应调用 ID，工具事件的 `result.ok` 为 `false` 且错误码为 `path_invalid`，最终仍是 `reason: "completed"`；换文件内容后，最终读取结果随之改变，而不是固定字符串。
